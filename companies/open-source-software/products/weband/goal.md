## 阶段 2（Phase 2）复现参考设备 App（2026-11-18 用户提出）

**内容**：复现参考设备的 Android App。参考安装包都在本机只读目录 `/home/whole/data/reawork/refdevice-files/`：1.3.1、1.4.0（2026-11-18 从 `refdevice-v1/` 移来）、1.5.0（最新，2026-11-18 加入）。阶段 1 用 1.4.0 验收。做出我们自己的 App，与 Weband 固件配合，补上原版 App 不支持的部分（例如按键确认配对 `button_confirm`、莫斯码配对）。

**起点**：阶段 1 的互通结论，加上本机只读资料里已有的 1.3.1 逆向资料（`refdevice-files/` 与 `refdevice` 下的 APK 分析、协议文档）。

**差异分析 1.3.1 → 1.4.0 → 1.5.0（2026-11-18 用户要求先做，已完成原生模块部分）**：报告在仓库外 `/home/whole/data/reawork/refdevice-files/analysis/app-diff-1.3.1-1.4.0-1.5.0.md`（只读资料，不入库）。方法：`dexdump` 反汇编原生 BLE 模块，三版对比 `const-string`；界面层在 Hermes 字节码里，没有反编译器，只粗看了关键词。要点：
- 不变：GATT（`…ef0/ef1/ef2`）、鉴权、录音传输（MBF1）、`device_status` 字段、按 `hw` 选升级包。
- 1.4.0 新增：能力协商 `device_features`/`caps`（鉴权后最多等约 9 s）；**配对方式由 App 按 `hw` 和 `caps` 选：`hw=1` 一律输码，`hw=2` 且 `caps` 含 `button_pair` 才走按键**；夜间定时关机、清空存储（先 `storage_info` 再带快照校验的 `storage_clear`）、跳过传输记录、壁纸持久化；新上报 `device_settings` / `device_diag` / `device_event`；一批新状态串。内置 v1 包 1.15.31。

- 对 Weband 的影响：
  1. **`hw=2` + `caps` 含 `button_pair`：开发版实测通过（2026-11-18，Weband `evidence/0048_v1_hw2_button_pair/`）**。原版 App 1.4.0 改发 `button_confirm`，单击电源键后 `paired ok method=button_confirm`，App 显示已连接、已加密。为此固件改了：`caps` 声明 `button_pair`（所有构建）；`device_features` 先于 `device_status`；按键的 `pair_ready` / `ok` / `expired` 带 `method` 与 `request_id`，`pair_ready` 带 `confirm_ms`；`request_id` 上限 64；按键窗口 60 s → 30 s（App 上限）。`hw` / `fw_version` 默认仍 1 / 1.15.35，实验用本地变量 `WEBAND_HW_ID=2 WEBAND_FW_VERSION=2.15.35`。
     - **已定（2026-11-18 用户）：正式版与开发版都默认报 `hw=2`、`fw_version` `2.15.35`（`68a9010`）**。代价：App 把设备当方屏版，升级选 v2 包（固件拒装），`fw_version` 按 2.x 比较，壁纸等按方屏处理。

     - 按键：加了调试日志（抖动、40 ms 以下按压、`WEBAND_KEY_DEBUG=1` 时记每次按下松开）。复测 5 次单击（180–360 ms）全部识别，1 次 20 ms 回弹被正确忽略；上次"第一次单击没反应"未复现。App 不显示按键提示文案，原因未查。
